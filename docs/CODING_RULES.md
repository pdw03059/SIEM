# MAZKION 코딩 규칙 (CODING_RULES)

이 문서는 MAZKION 저장소에 코드를 쓰는 모든 사람(발주자, 팀장, 작업자, 외부 기여자)이 따르는 규칙입니다.
근거는 `CLAUDE.md`의 "반드시 지킬 원칙", `DECISIONS.md`의 유지보수성 원칙(2026-10-30), `docs/PLAN.md` 10-3(오류 기록)·14장(보안)입니다.
규칙이 바뀌면 이 문서와 `DECISIONS.md`를 함께 고칩니다.

> 등록 표·오류 코드 패턴의 **실제로 빌드되는 예제**: `docs/examples/registry/` (`make -C docs/examples/registry test`)

## 1. 맨 첫 줄: 이름의 유래 (지우거나 바꾸지 않음 — 발주자 지시)

모든 C 소스(`.c`)·헤더(`.h`)·목록 파일(`.def`)·Makefile, TypeScript 진입 파일, 웹사이트 첫 페이지, 모듈 README의 **1번 줄**은 아래 문구입니다.
문구는 새로 쓰지 말고 기존 파일 1번 줄을 그대로 복사합니다(`head -1 stage1/src/minilogd.c`).

C·헤더·`.def` (원본: `stage1/src/minilogd.c` 1번 줄):
```c
/* MAZKION(마즈키온) — 성경 속 왕의 사관 '마즈키르(מַזְכִּיר, 삼하 8:16)' + 뿌리 '자카르(זָכַר, 기억하다)' + 빛보다 빠른 '-ion': "모든 일을 빠짐없이, 가장 빠르게 기록하고 결코 잊지 않는 자" (ORIGIN.md) */
```

Makefile (원본: `stage1/Makefile` 1번 줄, `#` 주석):
```make
# MAZKION(마즈키온) — 왕의 사관 '마즈키르' + '자카르(기억하다)' + '-ion': "모든 일을 빠짐없이, 가장 빠르게 기록하고 결코 잊지 않는 자" (ORIGIN.md)
```

Markdown·HTML: `<!-- ... -->` 안에 C 문구와 같은 본문(이 문서 1번 줄 참고).
TypeScript 진입 파일: `/* ... */` 안에 C 문구와 같은 본문.

- 1번 줄 앞에 빈 줄, `#!`, BOM, `#pragma once` 등 어떤 것도 두지 않습니다. 셸 스크립트처럼 `#!`가 반드시 1번 줄이어야 하는 파일만 예외로 2번 줄에 둡니다.
- 검사: `head -1 <파일> | grep -q 'MAZKION(마즈키온)'` — CI에서 모든 대상 파일에 대해 실행할 예정입니다.

## 2. 디렉터리 구조와 이름

```
include/mz_<모듈>.h        공개 인터페이스(다른 모듈이 볼 수 있는 유일한 것)
src/<모듈>/                 구현. 모듈 하나 = 책임 하나
src/<모듈>/README.md        무엇·왜·확장하는 법
src/<모듈>/<모듈>_*.c       구현 파일(내부 전용 헤더는 src/<모듈>/<모듈>_internal.h)
tests/<모듈>/               그 모듈의 단위 시험
include/mz_errors.def       전 제품 오류 코드 목록(5장)
include/mz_config_defaults.h  설정 기본값(6장)
```

| 대상 | 규칙 | 예 |
|---|---|---|
| 공개 함수 | `mz_<모듈>_<동사>` | `mz_store_append()` |
| 공개 타입 | `mz_<이름>_t` | `mz_store_t`, `mz_err_t` |
| 매크로·상수 | `MZ_<모듈>_<이름>` 대문자 | `MZ_STORE_SEGMENT_MAX` |
| 파일 내부 함수 | `static`, 접두어 없어도 됨 | `static int parse_pri(...)` |
| 헤더 가드 | `MZ_<모듈>_H` | `#ifndef MZ_STORE_H` |

- 다른 모듈은 **`include/`의 헤더만** `#include` 합니다. `src/다른모듈/*_internal.h`를 가져오면 리뷰에서 거절합니다.
- 모듈 하나의 책임을 README 첫 문단에 한 문장으로 쓸 수 없으면 모듈을 나눕니다.
- README 구성: `## 무엇` / `## 왜` / `## 확장하는 법`(등록 표 위치, 추가할 파일, 시험 추가 방법) / `## 시험`.

## 3. 주석 규칙

C 코드는 **실행·선언이 있는 줄마다 한국어 주석**을 답니다(학습 목적, 발주자 결정 2026-10-29). 주석은 다음 셋 중 필요한 것을 담습니다.
- **무엇을**: 이 줄이 하는 일
- **왜**: 이렇게 한 이유(다른 방법을 쓰지 않은 이유, 현장 사례)
- **C 개념**: 처음 보는 사람이 모를 문법·함수(`static`, 포인터, `size_t`, `_r` 함수 등)

`{`, `}`만 있는 줄과 빈 줄은 예외입니다. 함수·구조체 위에는 블록 주석으로 역할·매개변수·반환값·소유권(7-4)을 씁니다.

나쁜 예:
```c
n = recv(fd, buf, sizeof buf - 1, 0);   /* recv 호출 */
i++;                                    /* i 증가 */
```
좋은 예:
```c
n = recv(fd, buf, sizeof buf - 1, 0);   /* 패킷 1개를 받습니다. 끝에 '\0'을 붙일 1바이트를 남기려고 -1 합니다 */
i++;                                    /* 다음 레코드로 넘어갑니다(헤더+본문을 이미 건너뛰었으므로 1만 증가) */
```
- 코드를 바꾸면 주석도 같은 커밋에서 고칩니다. 코드와 다른 주석은 주석이 없는 것보다 나쁩니다.
- 영어 용어는 처음 한 번 괄호로 병기합니다: "블룸 필터(Bloom filter)".

## 4. 등록 표(registration table) 패턴 — 확장은 파일 추가로

새 **수집기 유형·파서·쿼리 명령어·대시보드·오류 코드**를 넣을 때 고치는 곳은 다음 두 곳뿐이어야 합니다.
1. 새 파일 1개 (예: `src/query/cmd_dedup.c`)
2. 등록 표에 한 줄

`if (strcmp(name, "head") == 0) ... else if ...` 같은 분기 사슬, 여러 파일에 흩어진 `switch`는 금지합니다.

### 4-1. 두 가지 방법과 선택 기준

| 방법 | 쓰는 곳 | 이유 |
|---|---|---|
| **구조체 상수 배열** (`static const mz_xxx_entry_t TABLE[]`) | 함수 포인터를 가진 등록 표: 수집기 유형, 파서, 쿼리 명령어, 대시보드 | 디버거로 보기 쉽고, 항목마다 함수·도움말·버전을 담기 좋음. 매크로 마법이 없어 처음 보는 사람도 읽기 쉬움 |
| **X-매크로** (`.def` 목록 + `#define X(...)` 후 `#include`) | 같은 목록에서 **여러 산출물**(열거형 + 문자열 표 + 매뉴얼)을 만들어야 하는 곳: 오류 코드, 설정 키, 지표 이름 | 열거형과 표가 어긋날 수 없음(목록이 한 곳). 개수 불일치는 `_Static_assert`로 컴파일 시 잡음 |

원칙: 기본은 구조체 배열, "열거형 값과 표가 반드시 짝을 이뤄야 할 때"만 X-매크로.

### 4-2. 구조체 배열 예 (쿼리 명령어)

```c
/* include/mz_query_cmd.h — 모든 명령어가 따라야 할 모양 */
typedef mz_err_t (*mz_cmd_fn)(mz_query_ctx_t *ctx, const mz_args_t *args);   /* 처리 함수 포인터 타입 */
typedef struct {
    const char *name;        /* 쿼리에서 쓰는 이름 */
    mz_cmd_fn   fn;          /* 처리 함수 */
    const char *help;        /* 한 줄 설명 — 매뉴얼 자동 생성에 사용(DECISIONS 2026-10-30) */
    uint16_t    since_ver;   /* 처음 생긴 쿼리 언어 버전 — 하위 호환 시험에 사용 */
} mz_cmd_entry_t;

/* src/query/cmd_registry.c — 새 명령어는 여기에 한 줄 */
static const mz_cmd_entry_t MZ_CMD_TABLE[] = {
    { "head",  mz_cmd_head,  "앞에서부터 N건만 남깁니다", 1 },   /* src/query/cmd_head.c */
    { "count", mz_cmd_count, "건수를 셉니다",             1 },   /* src/query/cmd_count.c */
};
#define MZ_CMD_COUNT (sizeof MZ_CMD_TABLE / sizeof MZ_CMD_TABLE[0])   /* 개수는 손으로 세지 않습니다 */
```
처리 함수 선언은 `src/query/cmd_list.h`에 한 줄씩 둡니다. 찾기(dispatch)는 표를 훑는 함수 하나만 두며, 명령어가 수백 개가 되어 느려지면 그때 정렬 + 이진 탐색으로 바꾸고 9장 규칙대로 벤치마크를 남깁니다.

### 4-3. 새 항목 추가 순서 (모든 등록 표 공통)
1. `src/<모듈>/<종류>_<이름>.c` 파일을 만들고 정해진 함수 모양을 구현
2. 등록 표에 한 줄 추가
3. `tests/<모듈>/test_<종류>_<이름>.c` 시험 추가
4. 모듈 README의 "확장하는 법" 목록에 이름 추가(자동 생성되면 생략)
5. 기능·시험·문서를 한 커밋으로

## 5. 오류 코드 단일 정의

- 전 제품 오류 코드는 **`include/mz_errors.def` 한 파일**에만 있습니다. 모듈별로 흩어 두지 않습니다(번호 충돌·누락 방지).
- 형식은 `docs/PLAN.md` 10-3과 같습니다. 코드 문자열은 `MZK-<모듈 3~4글자>-<4자리 번호>`.

```c
/* MZ_ERR(열거형 이름, 코드, 심각도, 사람 말 요약, 영향, 원인 후보, 조치) */
MZ_ERR(MZ_OK,                  "MZK-GEN-0000", "정보", "정상 처리되었습니다.", "없음.", "없음.", "없음.")
MZ_ERR(MZ_ERR_COL_NO_INPUT,    "MZK-COL-0103", "경고", "수집기가 정해진 시간 동안 로그를 받지 못하고 있습니다.",
       "이 수집기를 쓰는 탐지 시나리오에 입력 공백이 생깁니다.",
       "① 송신 장비 설정 변경 ② 방화벽 차단 ③ 장비 재부팅",
       "송신 장비의 전송 대상 확인 후 sys.collectors에서 마지막 수신 시각 확인")
```

이 한 목록에서 다음을 만듭니다(예제 `registry_demo.c` 참고).
- `typedef enum { ... MZ_ERR__COUNT } mz_err_t;` — 모든 함수의 반환 타입
- `MZ_ERR_TABLE[]` — 코드·요약·영향·원인·조치 문자열 표
- 오류 매뉴얼 페이지(빌드 시 자동 생성 예정), `sys.errors`의 코드 설명

**관련 객체·추적 ID·기술 상세(errno, 시스템 호출)** 는 발생 시점마다 달라지므로 목록이 아니라 오류 기록 함수의 인자로 넘깁니다.
```c
mz_errlog(ctx, MZ_ERR_COL_NO_INPUT, &(mz_errobj_t){ .collector_id = id, .node = node }, errno, "recvfrom");
```
같은 오류의 반복 묶기(처음·마지막 시각, 횟수)는 기록 모듈이 처리하므로 호출하는 쪽은 신경 쓰지 않습니다.

오류 코드 추가 방법:
1. `mz_errors.def`의 해당 모듈 구역 끝에 한 줄 추가. 번호는 그 모듈의 마지막 번호 + 1
2. 요약은 "무엇이 / 왜 / 어디서"가 드러나는 한 문장, 영향·원인 후보(가능성 높은 순)·조치 칸을 **비우지 않음**
3. 이미 출시된 코드의 번호·의미는 바꾸지 않습니다. 쓰지 않게 되면 `폐기` 표시만 하고 번호를 재사용하지 않습니다
4. 그 오류가 실제로 나는 경로를 시험에 추가

## 6. 상수·설정 기본값 단일 정의 (매직 넘버 금지)

| 종류 | 두는 곳 | 예 |
|---|---|---|
| 제품 전체 상수 | `include/mz_limits.h` | `MZ_PATH_MAX`, `MZ_MSG_MAX` |
| 모듈 상수 | `include/mz_<모듈>.h` (공개) 또는 `src/<모듈>/<모듈>_internal.h` | `MZ_STORE_SEGMENT_BYTES` |
| 설정 기본값 | `include/mz_config_defaults.h` (X-매크로: 키, 타입, 기본값, 최소, 최대, 설명) | `MZ_CFG(listen_port, int, 5140, 1, 65535, "수신 포트")` |
| 디스크 포맷 상수 | `include/mz_format_<이름>.h` | 매직 바이트, 버전 번호(8장) |
| 오류 코드 | `include/mz_errors.def` (5장) | |

- 코드 본문에 `0`, `1`, `-1`, 배열 인덱스 `sizeof` 계산 이외의 숫자를 직접 쓰지 않습니다. `65535`, `512`, `"./data"`는 이름 붙은 상수로.
- 단위를 이름에 붙입니다: `_MS`, `_SEC`, `_BYTES`, `_COUNT`.
- 설정 기본값을 코드 여러 곳에서 다시 쓰지 않습니다. 설정 문서·검증(최소·최대)·`sys.config` 뷰는 같은 목록에서 만듭니다.

## 7. 함수·파일·상태·메모리·오류 반환·안전 규칙

### 7-1. 크기 상한과 중복
- 함수는 **60줄**(주석 포함, 빈 줄 제외) 안팎, 파일은 **800줄** 안팎을 넘기지 않습니다. 넘으면 나누는 것이 기본이고, 못 나누는 이유는 함수 위 주석에 적습니다.
- 같은 코드(대략 5줄 이상 같은 흐름)를 두 번 쓰게 되면 공용 함수로 뺍니다. 두 모듈이 함께 쓰면 `src/common/` + `include/mz_common_*.h`로.

### 7-2. 전역 상태 금지 — 문맥(context) 구조체 전달
- 바꿀 수 있는 전역 변수·`static` 지역 상태를 두지 않습니다. 모듈 상태는 구조체에 담아 첫 인자로 넘깁니다.
- 허용 예외: ① 읽기 전용 표(`static const`) ② 신호 처리 깃발(`static volatile sig_atomic_t`) — 신호 처리 함수는 인자를 받을 수 없기 때문. 예외는 주석에 이유를 적습니다.

```c
typedef struct mz_store mz_store_t;                       /* 불완전 타입: 내부 구조를 헤더에 드러내지 않습니다 */
mz_err_t mz_store_open(const mz_store_cfg_t *cfg, mz_store_t **out);   /* 만들기 — 성공 시 *out에 새 객체 */
mz_err_t mz_store_append(mz_store_t *st, const void *rec, size_t len); /* 사용 — 상태는 st 안에만 */
void     mz_store_close(mz_store_t *st);                  /* 정리 — NULL을 넘겨도 안전 */
```

### 7-3. 오류 반환 규칙
- 실패할 수 있는 모든 함수는 **`mz_err_t`를 반환**하고 결과는 출력 매개변수(out-param, 마지막 인자, 이름 `out`/`out_*`)로 돌려줍니다.
- 실패하면 `*out`을 건드리지 않거나 `NULL`/0으로 둡니다(중간 상태를 남기지 않음).
- 반환값은 반드시 확인합니다. 공개 함수 선언에 `__attribute__((warn_unused_result))`(매크로 `MZ_MUST_CHECK`)를 붙입니다.
- 정리가 필요한 함수는 `goto fail;` 한 곳에서 거꾸로 정리합니다(C에서 흔한 정리 관용구).
- `-1`/`NULL`만 돌려주고 이유를 버리는 함수를 공개 인터페이스에 두지 않습니다.

### 7-4. 메모리 소유권 (누가 해제하는가)
| 모양 | 소유권 |
|---|---|
| `mz_x_open/new(..., mz_x_t **out)` | 호출한 쪽이 소유, 같은 모듈의 `mz_x_close/free()`로만 해제 |
| `const char *mz_x_name(const mz_x_t *)` | **빌려줌**. 객체가 살아 있는 동안만 유효, 해제 금지 |
| `mz_err_t mz_x_dup_name(..., char **out)` | 새로 할당해 넘김. 호출한 쪽이 `mz_free()`로 해제 |
| 인자로 받은 포인터 | 함수는 보관하지 않음. 보관해야 하면 복사하고 README·주석에 명시 |

- 모든 공개 함수 주석에 `소유권:` 줄을 씁니다. `free` 계열 함수는 `NULL`을 받아도 아무 일도 하지 않게 만듭니다.
- 해제한 포인터는 바로 `NULL`로 둡니다. 시험 빌드에서 ASan으로 누수·이중 해제를 잡습니다(10장).

### 7-5. 문자열·버퍼 (PLAN 14장, 로그 내용은 믿지 않는 입력)
- 금지 함수: `strcpy`, `strcat`, `sprintf`, `vsprintf`, `gets`, `strtok`(스레드 안전하지 않음), `atoi`(오류를 알 수 없음).
- 대신: `snprintf`(반환값으로 잘림 확인), 길이를 함께 넘기는 `mz_buf_t {char *p; size_t len, cap;}`, `strtol`/`strtoull` + `errno`·끝 포인터 확인.
- 로그 원문은 `'\0'` 종료 문자열로 가정하지 않고 **(포인터, 길이)** 쌍으로 다룹니다. 원문 안에 `'\0'`이 있어도 안전해야 합니다.
- 배열·버퍼에 쓰기 전 남은 크기를 먼저 확인합니다.
```c
int n = snprintf(path, sizeof path, "%s/%s.dat", dir, day);   /* 경로를 만듭니다 */
if (n < 0 || (size_t)n >= sizeof path) return MZ_ERR_PATH_TOO_LONG;   /* 잘렸으면 쓰지 않고 오류 — 잘린 경로로 엉뚱한 파일을 여는 것 방지 */
```
- 포맷 문자열에 외부 값을 직접 넣지 않습니다: `printf(msg)` 금지, `printf("%s", msg)`.

### 7-6. 정수 넘침
- 크기·개수·오프셋은 `size_t`/`uint64_t`. 부호 있는 값과 섞어 비교하지 않습니다(`-Wsign-compare`).
- 곱셈·덧셈으로 할당 크기를 만들 때는 넘침 확인을 먼저 합니다. GCC·Clang의 `__builtin_mul_overflow`를 `mz_safe.h`의 `mz_mul_size()`로 감싸 씁니다.
```c
size_t bytes;                                                 /* 할당할 전체 크기 */
if (mz_mul_size(count, sizeof(rec_t), &bytes)) return MZ_ERR_TOO_LARGE;   /* count × 크기가 넘치면 거절 */
```
- 디스크·네트워크에서 읽은 길이 값은 상한(`MZ_MSG_MAX` 등)과 남은 바이트 수를 모두 확인한 뒤 씁니다.

## 8. 저장 포맷·통신 메시지 버전 규칙

- 디스크 파일·세그먼트·인덱스·백업·노드 간 메시지·API 응답 스키마에는 **처음부터 버전 번호**를 넣습니다. 파일은 `[매직 4바이트][포맷 버전 uint16][헤더 길이 uint16]...`로 시작합니다. 헤더 길이를 함께 두면 뒤에 칸이 늘어나도 옛 판독기가 건너뛸 수 있습니다.
- 바이트 순서(리틀 엔디언 고정)와 각 칸의 크기를 `include/mz_format_<이름>.h`에 주석으로 적습니다. 구조체를 통째로 `fwrite` 하지 말고 칸별로 인코딩·디코딩 함수를 둡니다.
- 버전을 올리는 변경에는 같은 커밋(또는 같은 PR)에 다음이 반드시 있어야 합니다.
  1. **마이그레이션**: 이전 버전 → 새 버전 변환 함수(`mz_<포맷>_migrate_v<N>_to_v<N+1>`). 등록 표에 한 줄(4장 패턴)
  2. **하위 호환 시험**: `tests/<모듈>/fixtures/v<N>/`에 이전 버전으로 만든 작은 표본 파일을 커밋하고, 새 코드가 그것을 읽거나 변환할 수 있는지 시험. 표본 파일은 합성 데이터만(12장, 고객 로그 금지)
  3. `DECISIONS.md`에 변경 이유, 릴리스 노트 초안에 사용자 영향
- 판독기는 모르는 **새** 버전을 만나면 추측하지 않고 오류 코드로 거절합니다.
- 쿼리 언어 함수·명령어 동작을 바꿀 때도 같은 원칙(현장 사례: `_time` 변환이 예고 없이 바뀜). 등록 표의 `since_ver`와 동작 시험으로 지킵니다.

## 9. 성능 코드 분리

- 성능 때문에 읽기 어렵게 쓴 코드(SIMD, 직접 만든 해시표, 잠금 없는 큐, 수동 루프 펼침 등)는 **별도 파일** `src/<모듈>/<이름>_fast.c`로 분리하고, 같은 일을 하는 **단순한 기준 구현**(`_ref.c`)을 함께 둡니다. 시험은 두 구현의 결과가 같은지 비교합니다.
- 파일 머리 주석에 반드시 적습니다.
```c
/*
 * 왜 복잡한가: 키워드 비교가 검색 시간의 70%를 차지해 SSE4.2 비교로 바꿈
 * 벤치마크: bench/bench_match.c, 1GB 합성 로그, 16코어
 *   기준 구현(_ref) 2.10 GB/s → 이 구현 6.80 GB/s (3.2배), 2026-11-xx, 커밋 abc1234
 * 되돌리는 법: CMake/Makefile의 MZ_MATCH_IMPL=ref
 */
```
- 수치 없이 "빠를 것 같아서" 복잡하게 쓰지 않습니다. 벤치마크 코드는 `bench/`에 두고 다시 돌릴 수 있게 합니다.

## 10. 빌드·품질 게이트

| 항목 | 기준 |
|---|---|
| 표준 | C11 (`-std=c11`). 필요한 POSIX 기능은 파일 맨 위 `#define _POSIX_C_SOURCE 200809L`로 명시 |
| 경고 | `-Wall -Wextra -Werror` 경고 0건. 권장 추가: `-Wshadow -Wconversion -Wformat=2 -Wvla` |
| 보안 옵션(배포 빌드) | `-O2 -D_FORTIFY_SOURCE=2 -fstack-protector-strong -fPIE -pie -Wl,-z,relro,-z,now` (PLAN 14장) |
| 시험 빌드 | `-fsanitize=address,undefined -fno-omit-frame-pointer -g`. 시험은 검사기 오류 0건이어야 통과 |
| 단위 시험 | 모듈마다 `tests/<모듈>/`, `make test`로 전부 실행. 종료 코드 0 = 통과 |
| 파서·통신 해석기 | 퍼징(fuzzing) 하네스 필수, 출시 전 정해진 시간 동안 충돌 0건 (PLAN 14장) |
| 커밋 | 기능 변경은 시험과 **같은 커밋**. 시험이 실패하는 커밋을 night 브랜치에 올리지 않음 (`WIP:` 커밋은 예외지만 다음 커밋에서 회복) |
| 단계 완료 | 경고 0, 단위·통합 시험 통과, 발주자 확인 후에만 완료 표시 |

예제 Makefile(`docs/examples/registry/Makefile`)의 `test`(경고=오류)와 `test-san`(검사기) 두 대상이 최소 형태입니다.

## 11. TypeScript 규칙 (웹 UI)

- 진입 파일(`src/main.tsx` 등)의 1번 줄은 1장의 유래 문구(`/* ... */`).
- 주석은 **블록 단위로 상세하게**: 컴포넌트·훅·함수 위에 무엇을, 왜, 받는 값·돌려주는 값, 상태가 바뀌는 시점을 씁니다. 줄마다 달 필요는 없습니다.
```ts
/*
 * useSearch — 검색어와 기간으로 /api/v1/search 를 부르고 결과·진행 상태를 돌려줍니다.
 * 왜: 검색 화면과 대시보드 위젯이 같은 호출·취소 로직을 쓰도록 한 곳에 모읍니다.
 * 취소: 새 검색이 시작되면 이전 요청을 AbortController로 끊어 늦게 온 응답이 화면을 덮지 않게 합니다.
 */
```
- `strict: true`, `any` 금지(불가피하면 이유 주석). 로그 값은 **텍스트로만** 표시하고 `dangerouslySetInnerHTML`·`innerHTML` 금지(PLAN 14장).
- 화면은 공개 REST API만 사용합니다(DECISIONS 2026-10-30). 대시보드·위젯도 4장처럼 등록 표 + 파일 추가로 늘립니다.
- 상수·API 경로·색상 토큰은 한 곳(`src/constants/`, `src/theme/`)에서 정의합니다.

## 12. 커밋·기록·클린룸·고객 정보

### 12-1. 커밋 메시지
```
<모듈>: <무엇을 바꿨는지 한 줄, 70자 이내>

왜 바꿨는지, 무엇을 시험했는지(명령과 결과 요약).
관련: DECISIONS 2026-11-01 / 이슈 #번호

Co-Authored-By: ...
Claude-Session: https://claude.ai/code/session_...
```
- **발주자가 직접 수정한 코드**는 제목 맨 앞에 `[owner]`를 붙입니다: `[owner] store: 파티션 이름 규칙 변경`.
- Claude 세션이 만든 커밋은 맨 끝에 `Claude-Session:` 줄을 붙입니다. 이 주소가 `docs/SESSIONS.md`의 대화방 링크가 됩니다.
- 작업 중단 대비 커밋은 제목을 `WIP:`로 시작하고 `PROGRESS.md`의 `진행 중 작업:`을 함께 갱신합니다.
- 외부 PR·AI 검토 의견을 반영한 커밋은 본문에 출처(이슈·PR 번호)를 적고, 채택 여부는 `docs/COMMUNITY.md`에 남깁니다.

### 12-2. 클린룸
- 상용 SIEM 제품의 디컴파일 코드·내부 구현·비공개 자료를 보지도, 옮기지도 않습니다. 비교가 필요하면 "기준 제품"이라고만 쓰고 블랙박스 측정 결과만 기록합니다.
- 공개 소스 코드를 참고하거나 차용하면 라이선스 호환성(AGPL-3.0)을 확인하고 `THIRD_PARTY.md`에 출처·라이선스·차용 범위를 적습니다. 공개 문서의 문장은 복사하지 않고 요약합니다.

### 12-3. 고객 정보 금지
- 고객사명, IP 주소, 서버명, 계정, 설정값, 로그 원문을 코드·주석·시험 데이터·커밋 메시지·이슈에 넣지 않습니다.
- 사례는 "금융사 A", "사례 B"처럼 익명화합니다. 시험 데이터의 IP는 문서용 대역(`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`), 도메인은 `example.com`, 이름은 합성 값을 씁니다.
- 실수로 올렸다면 덮어쓰는 커밋으로 끝내지 말고 즉시 팀장·발주자에게 알립니다(이력 정리가 필요).
