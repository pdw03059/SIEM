- 실사용 지표(파싱·정규화·시나리오 포함 EPS)는 원문 UDP 수집 성능과 분리해 측정한다.
- 설계 전제: 저장 엔진·인덱스·수집 경로는 이 목표를 기준으로 설계하되, 달성 가능성은 docs/ARCHITECTURE.md의 병목 가설과 단계별 실측으로 검증한다. 목표와 달성 결과를 명확히 구분한다.

## 6. 수집·처리 범위 추가 (2026-10-30, 발주자 요청)
모든 유형의 수집 모델과 관련 프로파일, 스트림 쿼리를 구현한다.

| 분류 | 범위 |
|---|---|
| 접속 프로파일 | SSH/SFTP, FTP, DB(계정·접속 문자열), REST API(토큰·OAuth), 클라우드 자격 증명, TLS 인증서. 비밀값은 암호화 저장 |
| 수집 모델: 네트워크 | Syslog UDP/TCP/TLS(RFC 3164·5424), SNMP Trap, NetFlow/sFlow/IPFIX |
| 수집 모델: 파일 | 파일 tail, 디렉터리 감시(패턴·날짜 경로·하위 디렉터리), 로테이션 처리, 멀티라인(로그 시작 정규식), 문자 인코딩 |
| 수집 모델: 원격 파일 | SFTP/FTP 주기 수집(이어받기 위치 기록) |
| 수집 모델: DB | 주기 쿼리 수집(기준 컬럼 증분), PostgreSQL·MySQL/MariaDB 기본, ODBC 경유 Oracle·MSSQL 등 |
| 수집 모델: 시스템 | Windows 이벤트 로그, Linux journald·auditd, 프로세스·성능 지표 |
| 수집 모델: API·메시지 | REST 폴링, Kafka 소비, 클라우드 감사 로그(오브젝트 스토리지 폴링) |
| 파서·정규화 | 정규식·구분자·JSON·키=값 파서, 필드 정규화 규칙, 수집 모델 = 수집 방식 + 파서 + 정규화 묶음 |
| 스트림 쿼리 | 수집 직후 실시간 변환·필터·라우팅·집계 파이프라인, 비동기 실행 옵션, 오류 격리 |
| 행위 프로파일 | 주기 쿼리로 사용자·장비별 기준 행위 학습, 시나리오에서 참조 |

배치: 수집 모델·접속 프로파일·파서는 A·B단계에 기본형, D단계 전까지 전체 유형 완성. 스트림 쿼리는 B단계, 행위 프로파일은 F단계.
예상 영향: 코드 약 2만~3만 줄 추가, 전체 일정 약 1.5~2개월 증가 (총 약 11~14개월).

## 7. 쿼리 언어·매뉴얼·제품 웹사이트 추가 (2026-10-30, 발주자 요청)
| 항목 | 범위 |
|---|---|
| 쿼리 언어 | 기준 제품 쿼리 명령어(FEATURES.md 6장), Splunk SPL, SQL을 공개 문서로 비교 분석해 장점을 합친 자체 언어 설계. 파이프(`검색 \| 명령 \| 명령`) 문법을 기본으로 하고 SQL 문법(`SELECT … FROM 테이블 WHERE …`)도 같은 엔진에서 실행. 문서 문장·예제 복사 금지, 문법은 독자 설계 |
| 쿼리 매뉴얼 | 명령어·함수마다 문법, 인자, 예제, 결과 예시, 관련 명령, 다른 제품 대응 명령(SPL·SQL 대응표)을 실은 상세 매뉴얼. 명령어 정의 한 곳(소스의 명령어 메타데이터)에서 매뉴얼을 자동 생성해 코드와 문서가 어긋나지 않게 함. 이름·분류·키워드·예제 전문 검색 |
| 제품 웹사이트 | 제품 이름 확정 후 제작. 제품 소개, 기능 목록 검색(FEATURES.md 기반), 쿼리 매뉴얼 검색, 설치 안내, 다운로드, 대기자 명단(수익 실험 E2). 상용 SIEM 웹사이트·매뉴얼 구성을 참고하되 문구·디자인 복제 금지. 정적 사이트(TypeScript)로 GitHub Pages 배포 |

배치: 쿼리 언어 설계 문서는 0단계(아키텍처와 함께), 구현은 B단계. 매뉴얼은 B단계부터 명령어가 늘 때마다 자동 갱신. 웹사이트 v0(소개·대기자 명단)는 이름 확정 직후, 기능·매뉴얼 검색은 C단계.

## 9. 운영 가시성 요구사항 (2026-10-30, 발주자 현장 경험)
| 요구 | 내용 |
|---|---|
| 통합 시스템 뷰 | 모든 객체 종류(수집기, 전달 서버, 테이블, 파서, 스트림 쿼리, 예약 쿼리, 시나리오, 프로파일, 티켓·소명, 사용자, 노드, 복제)마다 **조인 없이 한 번에** 조회되는 시스템 뷰 1개. 예: `sys.collectors` = 이름·종류·노드·상태·EPS·바이트·마지막 수신·원본 지연·오류 수·설정 요약. 쿼리 언어·REST API·웹 UI가 같은 뷰를 씀. 외부 DB 없음(DECISIONS 참고) |

| 대시보드 품질 | 국내 APM 제품 대시보드 수준의 실시간·고밀도·직관적 화면을 목표. 공개된 화면은 수준 참고용일 뿐 디자인·구성 복제 금지. 1초 갱신, 수천 객체에서도 끊김 없는 렌더링, 다크/라이트 테마, 드릴다운 |
배치: 통합 시스템 뷰는 A단계부터(수집기 먼저), 자동 등록 대시보드와 품질 목표는 C단계 필수 완료 조건.

## 10. 저장 보호·백업·오류 기록 요구사항 (2026-10-30, 발주자 요청)

### 10-1. 테이블별 저장 설정
| 기능 | 내용 |
|---|---|
| 암호화 | 테이블마다 저장 암호화 켜기/끄기(AES-256-GCM). 키는 테이블별로 분리하고, 마스터 키로 감싸 보관. 키 교체(rotation) 시 새 데이터는 새 키, 옛 데이터는 백그라운드 재암호화. 키 접근은 감사 기록. 공공 납품용 검증필 암호모듈(KCMVP) 교체 가능 구조 |
| 압축 | 테이블마다 알고리즘·수준 선택(예: 빠른 lz4 / 고압축 zstd 1~19). 압축률·CPU 사용량을 sys.tables에 실시간 표시, 변경 시 다음 파티션부터 적용 |
| 생명주기 | 테이블마다 단계 지정: 뜨거움(빠른 디스크) → 따뜻함(일반 디스크) → 차가움(대용량·고압축) → 보관(외부 저장소) → 삭제. 기간 기준 자동 이동, 법적 보존 잠금(legal hold) 시 삭제 금지, 삭제·이동은 모두 감사 기록 |
| 위변조 방지 | 파티션마다 해시 체인을 남겨 저장 후 변경 여부를 검증(개인정보 접속기록 위변조 방지 의무 대응) |

### 10-2. 자동 백업
| 기능 | 내용 |
|---|---|
| 대상 | 테이블별, 서버(노드)별, 설정·메타데이터(SQLite) 전체 |
| 방식 | 일정에 따라 자동 실행. 전체 + 증분 백업, 백업 디스크·원격 서버·오브젝트 저장소로 보냄 |
| 검증 | 백업마다 해시 검증, 주기적으로 **복원 시험을 자동 실행**해 "복원되는 백업"인지 확인 |
| 보관 | 백업 보관 기간·개수 정책, 오래된 백업 자동 정리 |
| 복원 | 테이블·기간 단위로 골라 복원, 다른 이름 테이블로 복원해 비교 가능 |
| 가시성 | sys.backups 뷰와 기본 대시보드: 마지막 성공·실패, 소요 시간, 크기, 다음 예정, 복원 시험 결과, 백업 디스크 잔량·가득 찰 예상일 |

### 10-3. 내부 오류 기록 — "누가 봐도 무슨 문제인지 아는 로그"
현장 문제: 기존 제품의 내부 오류 로그는 읽어도 무슨 문제인지 모르는 경우가 많다(예외 이름·스택만 남음).
| 원칙 | 내용 |
|---|---|
| 오류 코드 | 모든 오류에 고유 코드(`MZK-<모듈>-<번호>`). 코드마다 매뉴얼 페이지 자동 생성 |
| 사람 말 요약 | 첫 줄은 "무엇이 / 왜 / 어디서"를 한국어(영어 병기)로 한 문장 |
| 영향 | 그래서 무엇이 멈췄거나 늦어지는지(수집 중단, 탐지 공백, 데이터 유실 가능 등) |
| 원인 후보·조치 | 가능성 높은 순서의 원인과 바로 할 조치, 확인용 쿼리 |
| 관련 객체 | 수집기·테이블·노드·사용자의 id와 이름, 추적 ID(같은 사건의 로그를 한 번에 묶음) |
| 기술 상세 | errno·시스템 호출·스택은 따로 접어 두는 칸에(개발자용) |
| 반복 묶기 | 같은 오류는 1건으로 묶고 처음·마지막 발생 시각과 횟수만 증가(로그 폭주 방지) |
| 실시간 검색 | 내부 로그도 MAZKION 자기 테이블(sys.errors)에 저장돼 쿼리·대시보드로 바로 검색 |
| 대시보드 | 오류 현황판(코드별·모듈별·노드별 추이, 새로 생긴 오류, 영향 큰 순서), 누르면 해당 객체 상세로 이동 |

예시:
```
[MZK-COL-0103] 경고 | 수집기 "방화벽-01"(노드 active-01)이 5분째 로그를 받지 못하고 있습니다.
영향: 이 수집기를 쓰는 탐지 시나리오 7개에 입력 공백이 생깁니다.
원인 후보: ① 송신 장비의 시스로그 설정 변경 ② 방화벽에서 UDP 514 차단 ③ 장비 재부팅
조치: 송신 장비에서 전송 대상 확인 → `sys.collectors where name="방화벽-01"`로 마지막 수신 시각 확인
추적 ID: 7f3a… | 처음 17:40:02, 마지막 17:45:02, 6회
```
배치: 오류 기록 형식과 sys.errors는 A단계부터(모든 코드가 처음부터 이 형식으로 오류를 남김), 암호화·압축·생명주기는 B단계, 자동 백업·복원 시험은 G단계, 대시보드는 C단계.

## 11. 자동 온보딩: 원본 로그 → 파서·대시보드·시나리오 자동 생성과 검증 (2026-10-30, 발주자 아이디어)
LLM을 직접 만들지 않는다. 1단은 폐쇄망에서도 도는 결정적 알고리즘(C), 2단은 선택형 보조 AI.

| 단계 | 방법 | 검증 |
|---|---|---|
| ① 형식 판별 | 시스로그(RFC3164/5424), JSON, key=value, CEF/LEEF, CSV, 멀티라인을 자동 판별. 알려진 장비 지문 라이브러리로 제조사·제품 추정 | 판별 신뢰도 표시 |
| ② 템플릿 추출 | 로그 템플릿 마이닝(Drain 계열 알고리즘)으로 같은 모양의 로그를 묶고 변하는 자리(변수)를 찾음 | 묶음별 대표 예시 표시 |
| ③ 필드 타입 추론 | 변수 자리마다 IP·포트·시각·사용자·URL·숫자·해시 등 타입 인식기 적용 | 샘플 전체에서 타입 일관성 % |
| ④ 파서 생성 | 템플릿+타입으로 정규식(백트래킹 없는 엔진 전용) 또는 key=value·JSON 파서를 생성, 표준 필드명으로 정규화 매핑 | **적용률**(파싱 성공 %), 따로 떼어 둔 검증용 샘플 적용률, 필드 누락 %, 처리 속도. 기준 미달이면 사람 확인 요청 |
| ⑤ 대시보드 생성 | 필드 타입에 맞는 기본 위젯(시간별 추이, 상위 출발지·목적지, 차단/허용 비율, 오류율 등)을 자동 배치, 자동 등록 대시보드에 추가 | 빈 위젯·0건 위젯 자동 제거 |
| ⑥ 시나리오 추천 | 로그 종류·필드에 맞는 탐지 규칙을 규칙 라이브러리(공개 Sigma 규칙 등, 라이선스 확인 후)에서 골라 추천 | **과거 데이터 백테스트**(예상 일 알림 수·상위 원인), **합성 공격 로그 주입 시 탐지 여부**, 일정 기간 **그림자 모드**(알림 없이 탐지만 기록) 후 활성화 |
| ⑦ 보조 AI(선택) | 필드의 의미 이름 붙이기, 정규화 매핑 제안, 시나리오 설명 문장 생성. 고객 내부에서 도는 공개 가중치 소형 모델(C/C++ 추론 엔진) 또는 고객이 허용한 외부 API. 모델 라이선스 확인 필수 | AI 제안은 반드시 ④·⑥의 같은 검증을 통과해야 적용. 원본 로그는 고객 동의 없이 외부로 보내지 않음 |

원칙: 자동 생성물은 모두 "제안 → 검증 수치 표시 → 사람 승인(또는 기준 이상 자동 승인 설정)" 순서. 승인 이력은 감사 기록.
배치: ①~④ B·D단계, ⑤ C단계, ⑥ D·F단계, ⑦ F단계 이후 선택 기능.

### 11-1. MAZKION 전용 로그 모델 로드맵 (2026-10-30, 발주자 방향)
목표: 어떤 로그가 들어와도 형식을 판별하고 파서·정규화·대시보드를 만들어 내는 **MAZKION 전용 모델**. 장비별 파서 앱을 사람이 하나하나 유지보수하는 부담을 없앤다.
| 원칙 | 내용 |
|---|---|
| 모델은 "파서를 만드는 데"만 쓴다 | 로그 1건마다 모델을 돌리지 않는다(초당 수십만 건에서 불가능). 새 로그 유형이 나타날 때만 모델이 템플릿·정규식·매핑을 생성하고, 이후엔 C 파서가 처리. 생성 결과는 캐시·재사용(연구 사례: LILAC, FSE 2024 — 템플릿 캐시로 LLM 호출을 수천 분의 1로 줄이고 정확도 향상) |
| 처음부터 만들지 않는다 | 공개 가중치 소형 모델(1B~8B급, 상업 이용 가능한 라이선스만)을 우리 로그 데이터로 미세조정(LoRA). 고객 내부 CPU·소형 GPU에서 추론 |
| 99%는 "검증으로 보장" | 모든 생성 파서는 검증 샘플 적용률·필드 정확도를 측정해 **99% 이상일 때만 자동 적용**, 미달이면 사람 확인 → 그 수정이 다시 학습 데이터가 됨. 자동 적용 범위(커버리지)는 학습이 쌓일수록 넓어짐 |
| 학습 데이터 | ① 공개 로그 데이터셋(Loghub 등, 라이선스 확인) ② 장비 매뉴얼 기반 합성 로그 ③ 고객 동의 시 **값을 지운 템플릿만** 수집(IP·사용자 등 실제 값은 외부로 나가지 않음) ④ 현장에서 사람이 고친 파서 |
| 데이터 수집은 지금부터 설계 | A단계부터 템플릿 추출·익명화·동의 관리 구조를 넣어 둔다(나중에 모으려면 늦음) |
| 측정 기준 | 로그 유형별 그룹 정확도·필드 정확도, 새 유형 자동 적용률, 처리 비용. 매 학습 버전마다 고정 시험셋으로 회귀 시험 |
배치: 데이터 수집 구조 A단계, 결정적 자동 온보딩 B~D단계, 첫 미세조정 모델 F단계(유료 고객 확보 후, 학습 GPU 비용 발생), 이후 지속 개선.

## 12. MAZKION AI — 앱 기능을 대신하는 자체 AI (2026-10-30, 발주자 지시, 단계 AI 신설)
생존 전략: 기존 통합로그 제품의 성능·기능 보완에 더해, 장비별 앱·수작업을 **우리 AI가 대신**한다. 목표 수준은 "숙련 엔지니어(클팀장) 수준의 정확도"이며, 정확도는 모든 작업에서 **검증 단계로 보장**한다.

| AI 기능 | 하는 일 | 정확도 보장 방법(자동 적용 조건) |
|---|---|---|
| 파서 생성 | 처음 보는 로그 → 형식 판별·템플릿·정규식·정규화 매핑 | 검증 샘플 적용률·필드 정확도 99% 이상 |
| 대시보드 생성 | 로그 종류·필드에 맞는 대시보드·위젯 구성, 자동 등록 | 모든 위젯 실데이터 조회 성공, 빈 위젯 0 |
| 마스킹 처리 | 개인정보·민감정보(주민번호·카드번호·전화·이메일·계좌·IP 등) 자동 탐지 → 마스킹 규칙 생성·적용(저장 전/조회 시/내보내기 시 선택) | 탐지 시험셋 재현율 99% 이상, 오탐 표본 검토, 마스킹 후 원문 복원 불가 확인 |
| 쿼리 작성 | 자연어 질문 → MAZKION 쿼리(파이프·SQL) 생성, 쿼리 설명·최적화·오류 수정 | 문법 검사 통과, 결과 미리보기와 의도 확인, 실행 비용 상한 확인 |
| 시나리오 작성 | 위협 설명·규정 요구 → 탐지 시나리오 생성(MITRE ATT&CK 매핑) | 과거 데이터 백테스트, 합성 공격 탐지, 그림자 모드 기간 통과 |
| 이벤트 해설 | 알림·티켓의 의미, 관련 로그, 조치 제안 요약 | 근거 로그 링크 필수(근거 없는 문장 금지) |
| 소명 지원 | 소명 요청 문안 작성, 소명 답변 요약·분류 | 담당자 승인 후 발송 |
| 장애 진단 | sys.errors·sys.* 뷰를 읽고 원인·조치 설명 | 근거 지표 링크 필수 |

구조
- **모델 2단 구성**: ① 폐쇄망용 MAZKION 전용 소형 모델(공개 가중치 모델을 우리 데이터로 미세조정, 고객 서버 CPU·소형 GPU에서 실행) ② 고객이 허용한 경우 대형 외부 모델 API 연결(같은 인터페이스). 어떤 모델이든 같은 검증을 통과해야 적용.
- **AI는 도구를 쓴다**: AI가 직접 답을 지어내지 않고 MAZKION 기능(sys.* 조회, 쿼리 실행, 파서 시험, 백테스트)을 호출해 확인한 결과로 답한다(근거 링크).
- **권한·감사**: AI가 만든 모든 변경은 제안 → 검증 → 사람 승인(또는 정책상 자동 승인) → 감사 기록. AI는 사용자 권한을 넘는 데이터를 볼 수 없다.
- **평가 시험셋(골든셋)**: 기능마다 고정 시험셋을 만들어 모델·프롬프트 버전마다 정확도를 측정하고, 떨어지면 배포 금지.
- **학습 데이터**: 11-1장 원칙(값 제거 템플릿, 고객 동의, 합성·공개 데이터, 사람 수정 이력).

배치: 데이터 수집 구조·AI 인터페이스(`include/ai.h`, 모델 교체 가능) A단계 설계 → 결정적 자동화 B~D → AI 단계(약 2~3개월): 외부 API 연결판 먼저(빠른 검증), 전용 소형 모델 미세조정은 유료 고객 확보 후. 전체 일정 약 13~17개월(베타).

## 13. 설치·배포 간편화 — 서버 100대도 오류 없이 (2026-10-30, 발주자 현장 경험)
현장 문제: 기존 제품은 이중화·수집 서버·분석 서버 설치가 어렵고 복잡하며 설치 과정 오류가 많다.
| 요구 | 내용 |
|---|---|
| 파일 하나 | 역할(분석·수집·전달·에이전트)별 정적 실행 파일 또는 한 파일 + 역할 선택. 외부 DB·자바 런타임 등 별도 설치 없음 |
| 폐쇄망 설치 꾸러미 | 인터넷 없이 설치하는 오프라인 패키지(RPM/DEB/tar), 서명·체크섬 검증 |
| 사전 점검 | 설치 전 자동 점검: OS·커널 버전, 포트 사용 여부, 디스크 공간·종류, 시계 동기화, 메모리, 방화벽, 권한(514 등 낮은 포트), SELinux. 문제는 사람 말 오류 + 고치는 명령으로 출력 |
| 첫 노드·참여 | `mazkion init`(첫 분석 노드) → 참여 토큰 발급 → 다른 서버는 `mazkion join <주소> --token <토큰>` 한 줄. 내장 인증기관이 노드 인증서를 자동 발급(관리자 암호 저장 없음, L06) |
| 이중화 | `mazkion init --ha` 또는 웹에서 "대기 노드 추가" 버튼. 복제 연결·초기 동기화·전환 시험까지 자동 |
| 100대 일괄 | 서버 목록 파일 하나로 SSH 일괄 설치·참여, 에이전트는 Linux 패키지·Windows 설치 파일(MSI, 그룹 정책 배포)·자동 등록. 진행률·실패 서버·원인을 한 화면에 |
| 같은 명령 반복해도 안전 | 설치·참여 명령은 몇 번 실행해도 같은 결과(멱등). 중간 실패 시 자동 되돌리기 |
| 설치 후 검증 | 설치 끝에 자동 시험: 노드 간 연결, 시험 로그 1건 수집 → 저장 → 검색, 복제 확인. "설치 보고서"로 남김 |
| 업그레이드 | 웹에서 순차 무중단 업그레이드, 사전 호환성 점검(L09·L10), 설정 자동 이관, 실패 시 되돌리기 |
| 제거 | 깨끗한 제거 명령(데이터 보존/삭제 선택) |
| 가시성 | sys.nodes·sys.agents에 설치 버전·상태·마지막 점검 결과 |
시험: 실험 서버에서 컨테이너로 가상 노드 100대를 띄워 설치·참여·업그레이드·제거를 매일 자동 시험(TEST_SERVER.md 6장).
배치: 단일 실행 파일·사전 점검·init/join은 A단계부터, 이중화 자동 구성·일괄 설치는 G단계, 무중단 업그레이드 G단계.

## 14. 보안 설계 — 공개 CVE·취약점 사례 반복 금지 (2026-10-30, 발주자 지시)
지금까지 공개된 SIEM·로그 수집기·로그 처리 공통 취약점(CVE 포함)을 조사해 같은 실수를 하지 않는다. 사례표·설계 규칙(SEC-xxx)·C 보안 코딩 규칙·의존 라이브러리 정책·출시 전 점검표는 `docs/SECURITY_LESSONS.md`(작성 중)를 따른다. 핵심: 로그 내용은 절대 해석·실행하지 않음, 웹 UI는 로그 값을 텍스트로만 표시, 모든 파서·통신 해석기는 퍼징 통과 필수, 백트래킹 없는 정규식 엔진, 외부 요청은 허용 목록(SSRF 차단), 쿼리 언어에 OS 명령 실행 기능 없음, 기본 계정·하드코딩 키 금지, 보안 컴파일 옵션·SBOM.

## 15. 사업·수익화 문서 (저장소 밖 비공개)
사업·수익 계획서(수익원, 구독 vs 영구, 경쟁력 평가, 첫 계약 플레이북, 36개월 현금흐름), 성공 확률 분석은 발주자 전용 문서(claude.ai 문서·MAZKION 프로젝트)에 둔다. 공개 저장소에는 올리지 않는다.

## 16. API 연동 — 필수 (2026-10-30, 발주자 지시)

### 16-1. 들어오는 API: MAZKION의 모든 기능을 API로 (API 우선 설계)
| 요구 | 내용 |
|---|---|
| 전 기능 API | 수집기·접속 프로파일·파서·테이블·저장 정책·쿼리 실행·예약 쿼리·스트림 쿼리·시나리오·프로파일·대시보드·위젯·티켓·소명·사용자·권한·노드·백업·sys.* 뷰까지 **화면에서 할 수 있는 모든 것을 API로**. 웹 UI도 같은 공개 API만 사용(화면 전용 숨은 기능 없음) |
| 표준 | REST + JSON, OpenAPI 명세 자동 생성(코드와 함께), 버전(`/api/v1`)·하위 호환 정책 |
| 인증·권한 | API 키(범위·만료·IP 제한), OAuth2 클라이언트 자격, 키별 권한 범위(읽기 전용·수집기 관리 등), 호출 감사 기록, 호출량 제한 |
| 대용량 | 쿼리 결과 스트리밍·페이지 처리, 비동기 작업(작업 ID로 상태 조회) |
| 이벤트 내보내기 | 웹훅(알림·티켓·수집기 상태 변화 발생 시 외부로 푸시), 재시도·서명 |
| 자동화 도구 | **n8n 전용 노드**(트리거: 알림·티켓 / 동작: 쿼리·수집기 생성·티켓 처리), 범용 HTTP로도 연동 가능한 예제, Python·Go 클라이언트, 명령줄 도구(`mazkion api …`) |
| 코드로 관리 | 수집기·시나리오·대시보드 설정을 파일로 내보내기/가져오기(설정을 코드처럼 버전 관리) |

### 16-2. 나가는 API: 외부 솔루션·위협정보(CTI)에서 정보 가져오기
| 요구 | 내용 |
|---|---|
| 범용 연동기 | API 주소(기본 URL·정책 URL)·API 키·인증 방식(API 키, Bearer, Basic, OAuth2, 인증서)·호출 주기·페이지 처리 규칙·응답 필드 매핑을 화면/API에서 설정하면 코드 없이 연동 |
| 결과 저장 | 가져온 정보는 테이블(이력) 또는 조회용 데이터셋(lookup, 예: 위협 IP 목록·NAC 단말 정보)으로 저장 → 시나리오·쿼리에서 바로 사용 |
| 대상 예 | 국내 NAC(단말·사용자 정보), 차세대 방화벽(정책·차단 이력), KISA C-TAS 등 위협정보 공유 플랫폼, 상용·공개 CTI 피드(STIX/TAXII 지원) |
| 연동 템플릿 | 자주 쓰는 솔루션은 연동 템플릿으로 제공(템플릿 = 설정 파일, 앱 개발 불필요). MAZKION AI가 API 문서·응답 예시로 매핑 초안 생성(PLAN 12장) |
| 안정성 | 시간 초과·재시도(지수 백오프)·실패 단계 구분 오류(DNS·프록시·TLS·인증·응답 형식), 프록시 지원(L11), 마지막 성공 시각·건수를 sys.integrations에 표시 |
| 보안 | API 키·비밀번호는 암호화 저장·화면 비표시·만료 경고, 호출 대상은 허용 목록(SSRF 차단, PLAN 14장) |

### 16-3. 외부 솔루션 명령 실행과 결과 가져오기 (발주자 지시, 필수)
외부 솔루션의 API를 **명령처럼 실행**하고 결과를 MAZKION으로 받아 온다(예: NAC에서 단말·사용자 조회, 방화벽 정책 조회·차단, 위협정보 플랫폼에서 지표 조회, 자산 관리 시스템 조회).
| 요구 | 내용 |
|---|---|
| 동작(액션) 정의 | 연동기마다 실행 가능한 동작을 등록: 이름, HTTP 방식·경로, 입력값, 결과 매핑. 템플릿·설정만으로 추가(코드 불필요), MAZKION AI가 API 문서로 초안 생성 |
| 어디서든 호출 | ① 쿼리 언어 명령(예: `… | ext nac.endpoint ip=src_ip` → 결과가 쿼리 결과 행으로 붙음) ② 시나리오 탐지 시 자동 실행 ③ 플레이북(여러 동작 연결) ④ 화면 버튼(이벤트·티켓에서 "NAC 조회", "방화벽 차단") ⑤ MAZKION 자체 API·n8n |
| 결과 처리 | 결과를 쿼리 결과·티켓 첨부·데이터셋·테이블로 저장, 다음 동작의 입력으로 연결 |
| 조회 vs 변경 구분 | 조회 동작은 바로 실행. **변경 동작(차단·격리·정책 수정)**은 동작별 권한, 승인 절차(사람 승인/정책 자동 승인), 사전 시험(dry-run 지원 시), 실행 횟수 제한, 되돌리기 동작 연결, 전부 감사 기록 |
| 안정성 | 시간 초과·재시도·병렬 제한, 실패 단계 구분 오류, 결과 캐시(같은 조회 반복 방지) |
| 보안 | 등록된 연동기·동작만 호출 가능(임의 URL 호출 금지, SSRF 차단), 비밀값 암호화, 사용자 권한 밖 동작 불가. 쿼리 언어의 OS 명령 실행 금지 원칙(PLAN 14장)과 구분: 외부 호출은 등록된 API 동작으로만 |
| 가시성 | sys.integration_actions: 동작별 호출 수·성공률·평균 응답 시간·마지막 오류·승인 대기 |

배치: API 골격·인증·OpenAPI 자동 생성은 A단계부터(모든 기능이 처음부터 API로 만들어짐), 전 기능 API 완성 C단계, 범용 연동기·CTI·웹훅·외부 명령 실행(조회 동작) D단계, 변경 동작 승인 체계·플레이북 D~G단계, n8n 노드·클라이언트 W·C단계, AI 매핑 초안 AI단계.
