# 프로젝트 계획 (발주자 요구사항 확정본)

## 1. 요구사항
| # | 요구사항 |
|---|---|
| R1 | 상용 SIEM에 있는 기능 전부 구현: 에이전트(수집), 전달 서버, 분석 서버, 이중화, 웹 UI, 대시보드, 실시간·배치 시나리오, 이상징후 탐지, 티켓·소명 |
| R2 | 각 기능을 기존 제품보다 더 좋게: 수집량·검색 속도·안정성·운영 가시성 |
| R3 | 언어는 C(C11). 웹 UI만 TypeScript + React |
| R4 | C 코드는 한 줄마다 한국어 주석, 단계별 학습 자료 제공 |
| R5 | 팀장(Claude)이 작업자(서브 에이전트)를 배정해 팀 단위로 개발 |
| R6 | 모든 보고 맨 위에 전체 진행률 표시 |
| R7 | 작업 시간 20:00~08:00(KST), 자동 시작·자동 이어하기. 08:00~20:00은 발주자 사용 |
| R8 | 공개 저장소(AGPL-3.0), 외부 개발자 의견 참고. 병합은 발주자 승인 |
| R9 | 상용화를 위한 법적 준비 자료(라이선스 준수, 독자 개발 증빙, 약관 초안) |
| R10 | 완성 후에도 유지보수·기능 확장 가능 |

## 5. 성능 목표
- 단일 서버 수집 30만 EPS 이상
- 하루 100GB 키워드 검색 수 초 이내
- 한 테이블 장애가 다른 테이블 적재에 영향 없음

## 6. 수집·처리 범위 추가 (2026-10-30, 발주자 요청)
모든 유형의 수집 모델과 관련 프로파일, 스트림 쿼리를 구현한다.

| 분류 | 범위 |
|---|---|
| 접속 프로파일 | SSH/SFTP, FTP, DB(계정·접속 문자열), REST API(토큰·OAuth), 클라우드 자격 증명, TLS 인증서. 비밀값은 암호화 저장 |
| 수집 모델: 네트워크 | Syslog UDP/TCP/TLS(RFC 3164·5424), SNMP Trap, NetFlow/sFlow/IPFIX |
| 수집 모델: 파일 | 파일 tail, 디렉터리 감시(패턴·날짜 경로·하위 디렉터리), 로테이션 처리, 멀티라인(로그 시작 정규식), 문자 인코딩 |
| 수집 모델: 원격 파일 | SFTP/FTP 주기 수집(이어받기 위치 기록) |
| 수집 모델: DB | 주기 쿼리 수집(기준 컬럼 증분), PostgreSQL·MySQL/MariaDB 기본, ODBC 경유 Oracle·MSSQL 등 |
| 수집 모델: 시스템 | Windows 이벤트 로그, Linux journald·auditd, 프로세스·성능 지표 |
| 수집 모델: API·메시지 | REST 폴링, Kafka 소비, 클라우드 감사 로그(오브젝트 스토리지 폴링) |
| 파서·정규화 | 정규식·구분자·JSON·키=값 파서, 필드 정규화 규칙, 수집 모델 = 수집 방식 + 파서 + 정규화 묶음 |
| 스트림 쿼리 | 수집 직후 실시간 변환·필터·라우팅·집계 파이프라인, 비동기 실행 옵션, 오류 격리 |
| 행위 프로파일 | 주기 쿼리로 사용자·장비별 기준 행위 학습, 시나리오에서 참조 |

배치: 수집 모델·접속 프로파일·파서는 A·B단계에 기본형, D단계 전까지 전체 유형 완성. 스트림 쿼리는 B단계, 행위 프로파일은 F단계.
예상 영향: 코드 약 2만~3만 줄 추가, 전체 일정 약 1.5~2개월 증가 (총 약 11~14개월).
