# 프로젝트 계획 (발주자 요구사항 확정본)

## 1. 요구사항
| # | 요구사항 |
|---|---|
| R1 | 상용 SIEM에 있는 기능 전부 구현: 에이전트(수집), 전달 서버, 분석 서버, 이중화, 웹 UI, 대시보드, 실시간·배치 시나리오, 이상징후 탐지, 티켓·소명 |
| R2 | 각 기능을 기존 제품보다 더 좋게: 수집량·검색 속도·안정성·운영 가시성 |
| R3 | 언어는 C(C11). 웹 UI만 TypeScript + React |
| R4 | C 코드는 한 줄마다 한국어 주석, 단계별 학습 자료 제공 |
| R5 | 팀장(Claude)이 작업자(서브 에이전트)를 배정해 팀 단위로 개발 |
| R6 | 모든 보고 맨 위에 전체 진행률 표시 |
| R7 | 작업 시간 20:00~08:00(KST), 자동 시작·자동 이어하기. 08:00~20:00은 발주자 사용 |
| R8 | 공개 저장소(AGPL-3.0), 외부 개발자 의견 참고. 병합은 발주자 승인 |
| R9 | 상용화를 위한 법적 준비 자료(라이선스 준수, 독자 개발 증빙, 약관 초안) |
| R10 | 완성 후에도 유지보수·기능 확장 가능 |

## 2. 원칙
- 클린룸: 상용 제품 디컴파일 코드·비공개 자료 미사용
- 저장소에 고객 정보 금지, 사례는 익명화
- 설계 결정은 DECISIONS.md에 결정자와 함께 기록

## 4. 단계 계획
| 단계 | 내용 | 비중 | 예상 기간 |

| A | 에이전트 → 전달 → 저장 → 검색 끝까지 동작 | 15% | 3~4주 |

| D | 실시간·배치 시나리오, 티켓 | 15% | 4~6주 |
| E | 소명(메일·소명 페이지·승인) | 10% | 3~4주 |
| F | 이상징후 탐지 | 10% | 3~4주 |
| G | 이중화, 운영 셸, 업그레이드 | 10% | 4~6주 |

## 5. 성능 목표
