# MAZKION 벤치마크 계획

> 상태: 시험 프로토콜 초안. 실행 결과가 기록되기 전까지 모든 목표는 미검증 목표이며, 벤치마크 결과를 주장하지 않는다.

## 1. 비교 원칙

- Logpresso와 Splunk는 각각 별도 시험표로 비교한다. 서로 다른 제품의 공개 수치·하드웨어·라이선스·측정 정의를 한 기준선으로 섞지 않는다.
- 공개 참고치(계획 문서에 기록된 기준 제품 270만 EPS, Splunk 인덱서 300GB/day)는 시험 조건이 불완전할 수 있다. 목표 설정 참고값이지 동등 조건의 실측 기준선이 아니다.
- 가능한 경우 동일 서버·동일 NIC·동일 디스크·동일 이벤트 데이터·동일 쿼리·동일 보존 설정으로 블랙박스 비교한다. 제품 계약/EULA/벤치마크 공개 제한을 먼저 확인한다.
- 비교할 수 없는 조건은 '비교 불가'로 표시하고 MAZKION 단독 재현 시험으로 대체한다. 추정치·이론 최대치와 실측치를 혼용하지 않는다.

## 2. 시험 환경 기록(필수)

각 실행마다 다음을 결과 파일에 기록한다.

- 제품/버전/빌드, OS·커널, CPU 모델·소켓·코어·스레드·NUMA, RAM, NIC 모델·속도·큐, 디스크 모델·펌웨어·파일시스템·마운트 옵션
- 전원/CPU governor, BIOS 설정, 가상화 여부, 컨테이너 제한, 네트워크 경로와 MTU
- 이벤트 크기(평균·p50·p95·최대), 로그 형식, 필드 수, 문자셋, 압축·암호화 여부
- 파싱·정규화·인덱싱·시나리오 사용 여부, 보존 기간, 복제/HA 여부
- 시험 도구·버전·명령행·설정 파일·난수 seed·데이터셋 해시
- 워밍업 시간, 측정 시간, 반복 횟수, 주변 부하, 캐시 상태

## 3. 시험군

### A. 수집·저장·인덱싱 EPS

- 입력: UDP, 고정 크기 이벤트(최소 3개 크기 구간 명시), 재현 가능한 시퀀스 번호 포함 데이터셋.
- 단계별 실행: 수신만, 수신+영속 저장, 수신+저장+인덱싱, 이후 파싱·정규화 포함 실사용 모드.
- 부하: 낮은 부하에서 시작해 목표 초과까지 단계적으로 올리고 각 단계 안정화 후 측정.
- 결과: offered EPS, received EPS, persisted EPS, indexed EPS, sequence gap, NIC/socket drop, 큐 백로그, CPU, RSS, 디스크 처리량·지연.
- 합격: 5,400,000 EPS 이상을 사전 합의된 지속 시간 동안 유지하고 유실 검증에서 손실 0. 초기에는 30분 지속 + 3회 반복, 장시간 안정성은 별도 24시간 시험.

### B. 노드당 일일 수집량

- 24시간 동안 600 GB 이상을 실제 수신·영속화한다. GB는 십진 단위(1 GB=10^9 bytes)로 통일하고 원본 입력량과 디스크 사용량을 별도 보고한다.
- 검색 부하를 동시에 실행한다. 검색 쿼리 유형·동시 사용자 수·실행 빈도를 고정하고 결과에 기록한다.
- 결과: 시간별 입력/저장량, 평균·최대 EPS, 디스크 사용량, 압축률, 인덱스 크기, 검색 지연, 백로그, 드롭·오류.

### C. 대용량 검색

- 데이터셋은 최소 25억 레코드 이상이며 동일 이벤트 분포·필드·시간 범위로 양쪽 제품에 적재한다.
- 쿼리는 전체 스캔, 시간 범위+키워드, 희귀 키워드, 흔한 키워드, 필드 필터·집계 등으로 고정하고 의미가 같도록 검증한다.
- 콜드 캐시와 웜 캐시를 분리한다. 동시 수집 부하가 있는 조건과 없는 조건을 모두 측정한다.
- 각 쿼리 최소 30회 반복을 권장하고 p50/p95/p99, 첫 결과 시간, 전체 완료 시간, CPU·메모리·읽기 바이트를 기록한다.
- 합격: 비교 대상의 동일 조건 응답 시간 대비 MAZKION p50 및 p95가 50% 이하인지 각각 보고한다. 평균값 하나로 꼬리 지연을 숨기지 않는다.

### D. 장애 격리

- 한 테이블의 쓰기 지연, 디스크 오류, 쿼리 폭주, 인덱스 오류를 주입한다.
- 다른 테이블의 ingest EPS·큐 지연·오류율이 사전 정의한 허용 범위 내에 유지되는지 확인한다.
- 복구 후 데이터 정합성·백로그 해소·중복/누락 여부를 검증한다.

## 4. 보고 형식

각 시험 결과는 reports/benchmarks/YYYY-MM-DD/<test-id>.md에 저장한다. 반드시 다음을 포함한다.

1. 시험 목적·제품 버전·환경 전체 명세
2. 데이터셋 해시·이벤트 크기 분포·쿼리 원문
3. 실행 명령·설정·워밍업·측정 시간·반복 횟수
4. 원시 결과(CSV/JSON)와 계산식
5. EPS/GB/day/검색 p50·p95·p99/손실률/CPU/RAM/디스크 지표
6. 실패·이상치·재시험 내역 및 재현 방법
7. 목표 대비 결과와 제한사항, 검토자

## 5. 공개·법적 검토

- 제3자 제품 벤치마크를 외부 공개하기 전에 계약·EULA·상표 사용·벤치마크 공개 제한을 확인한다.
- 제품 로고·화면·문서·비공개 자료를 복제하지 않는다.
- 외부 공개 시 장비·버전·시험 조건·원시 데이터·측정 스크립트를 함께 제공할 수 있는 범위에서 투명하게 공개한다.

## 6. 목표와 실측의 구분

| 상태 | 표현 |
|---|---|
| 계획만 존재 | 목표 / 미검증 |
| 자체 시험 완료 | MAZKION 단독 실측 결과 |
| 동일 조건 비교 완료 | 특정 버전·환경에서의 비교 결과 |
| 반복·독립 재현 완료 | 재현된 벤치마크 결과 |

한 번의 결과나 벤더 공개 참고치를 근거로 'Splunk/Logpresso보다 2배 빠르다'고 일반화하지 않는다.
