# FEATURES — 기능 체크리스트

> 상태: 초안(0단계). 작성: 기능 분석 담당 작업자. 검토·커밋: 팀장.

## 작성 방법

- **자료원**: 기준 제품(상용 SIEM X, 이하 “기준 제품”)의 **공개 문서**(제품 설명서, 설치 안내서, 쿼리 명령어 설명서, REST API 목차, 앱 개발 안내서, 릴리스 노트)와 공개 앱 스토어 목록만 읽었다. 출처 URL 목록은 공개 저장소 노출을 막기 위해 이 파일에 넣지 않고 팀장 작업 공간에 따로 보관한다.
- **클린룸**: 디컴파일·패키지 내부·비공개 자료는 보지 않았다. 문서 문장·예제·스크린샷은 옮기지 않고 기능 사실만 우리 말로 요약했다. 명령어·함수 이름은 사실 정보로 적되, 제품 고유 접두어가 붙은 명령어는 `(접두어)-`, `(SOAR)-`로 일반화했다.
- **고객 정보 없음**: 고객사명·IP·로그 원문 없음. 현장 경험은 “[현장 개선]”으로 표시하고 익명 일반화했다.
- **우리 방향**: 발주자 요구 “기준 제품의 모든 기능 + 더 좋게”. 개선점은 발주자 현장 경험(테이블 잠금 정체, 미래 날짜 파티션, 배치 소급, 에이전트 ID 충돌, 소명 링크 미표시, RPC 무한 대기, 런타임 메모리 튜닝, 업그레이드 설정 이관, 전달 지연 가시성)을 우선 반영했다.

## 범례

- **ID**: 분류 코드-번호 (예: `COL-003`). 쿼리 명령어는 `QC-번호`, 함수 분류는 `QF-번호`.
- **단계**: 0=명세·준비 / A=에이전트→전달→저장→검색 최소 동작 / B=쿼리 언어·인덱스·성능·스트림 쿼리 / C=웹 API·웹 UI·대시보드 / D=실시간·배치 시나리오·티켓·전체 수집 모델 / E=소명 / F=이상징후·행위 프로파일 / G=이중화·운영 셸·업그레이드
- **우선순위**: 필수(없으면 제품이 성립하지 않음) / 중요(현장 운영에 꼭 필요) / 선택(후순위·플러그인)
- **[현장 개선]**: 발주자 현장 경험에서 나온 개선 요구.

## 문서에서 확인하지 못한 영역 (솔직하게)

- REST API는 영역(약 50개) 목차만 확인했다. 엔드포인트별 요청·응답 형식은 읽지 않았다(필요 시 C단계 착수 전 추가 조사).
- 구버전(SIEM 3.x·4.0 계열) 화면 설명서는 일부(연관분석·피벗·대시보드 기능 소개)만 읽었다. 4.0 계열 고유 기능 중 5.0에서 빠진 것이 있을 수 있다.
- 에이전트-서버 통신 프로토콜, 저장 파일 포맷, 인덱스 내부 구조, 복제 프로토콜은 공개 문서에 없다(클린룸 원칙상 조사하지 않음). 우리 설계로 새로 정한다.
- 시나리오 빌더의 “수용 가능 위험” 산정 방식과 위험 점수(리스크 모델) 산식의 세부는 문서에서 충분히 설명되지 않았다.
- 메신저(슬랙·팀즈 등) 연동과 다수 SaaS 수집기는 기본 문서가 아니라 개별 앱 설명서에 있어 앱별 상세(100여 개)는 읽지 않았다. 스토어 목록·분류 수준만 확인했다.
- 플레이북 편집기 노드별 세부 속성, 보고서 서식 항목 세부, 위젯별 속성 페이지는 제목 수준으로만 확인했다.
- 유닉스(AIX·HP-UX·솔라리스) 에이전트 설치 절차는 “별도 문의”로 되어 있어 공개 문서에 없다.
- 성능 수치(인덱싱·검색 배수, 1티어 일 처리량 등)는 문서상 주장만 있고 측정 조건이 없다. 벤치마크 목표는 우리 측정으로 따로 정한다.
- “접속 프로파일”은 기준 제품에서 외부 접속 정보 저장소를 뜻한다. 발주자가 말한 “접속 프로파일(접속 행위 기준선)”에 해당하는 별도 기능은 문서에서 찾지 못했다(행위 프로파일로 구현하는 예시만 있음).
- 머신러닝 모델 학습 파라미터·평가 지표, 이상탐지 결과를 시나리오에 연결하는 방식의 세부는 확인하지 못했다.
