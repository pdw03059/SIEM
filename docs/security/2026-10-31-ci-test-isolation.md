# 보안 검토 기록 — CI 시험 격리 (자동화 2-1단계, 2026-10-31)

CLAUDE.md "아키텍처 보안 검토"에 따른 기록입니다. 등급은 심각 / 높음 / 보통 / 낮음 / 확인 불가로 표시합니다.

## 1. 범위와 위협 가정
- **대상**: `.github/scripts/test/`의 네트워크 격리 시험과 GitHub 제공 실행기(Ubuntu 24.04)
- **목적**(발주자 결정): 시험 프로그램이 **실수로** 네트워크에 나가지 않는지 검증합니다. 악성 코드가 탈출하는 것을 막는 샌드박스가 아닙니다.
- **공격자 가정**: 없음. 이번 범위의 위협은 "우리 코드나 의존 라이브러리가 의도하지 않게 외부와 통신하는 것"입니다.

## 3. 발견 사항

### F-01 [보통] 격리 안에서 로컬 서비스 소켓에 잠재적으로 접근할 수 있음
- **위치**: 실행기의 `/run/dbus/system_bus_socket`, `/run/systemd/resolve/io.systemd.Resolve`, `/run/systemd/journal/socket`, `/run/systemd/journal/stdout`, `/dev/log`
  - 검사 코드: `.github/scripts/test/harness/local-probe.mjs`의 `SERVICE_SOCKETS`
  - Docker 소켓(`/run/docker.sock`)은 **권한 없음**이었습니다. `--clear-groups`로 docker 그룹이 빠졌기 때문입니다.
- **판정 근거**: 파일 시스템 권한(`access(W_OK)`) 기준의 **잠재적 접근 가능성**입니다. 실제로 접속해 보지는 않았습니다.
- **시나리오**: 격리 안의 시험 프로그램이 실수로든 의존 라이브러리 때문이든 systemd-resolved 창구를 쓰면, 격리 밖에서 DNS 조회가 대신 이뤄질 수 있습니다. 조회하는 이름에 값이 실리면 DNS를 통해 정보가 나갈 수 있습니다. D-Bus로는 다른 시스템 서비스에 요청을 보낼 수 있습니다.
- **실제 영향 범위**: 지금 시험 코드는 이 소켓들을 쓰지 않습니다. 실행기의 이름 조회 설정에서 격리 안 이름 조회는 실패했습니다(EAI_AGAIN). 그래서 **현재 시험 결과가 거짓 통과일 가능성은 낮습니다.** 다만 "네트워크 격리 = 외부 통신 없음"을 보장하지는 못합니다.
- **journald**: 읽을 수 있는 설정 파일 기준으로 원격 전달 설정 단서가 없었습니다(ForwardToSyslog, journal-upload, rsyslog 전달 규칙). journald를 통한 외부 유출 가능성은 낮지만, 설정을 다 읽었다는 보장은 없으므로 **확인 불가**로 남깁니다.
- **해결책** (후속 과제, 이번 범위 밖): 파일 시스템 격리(mount namespace)로 격리 안에서 `/run`과 `/dev/log`를 가립니다. 또는 시험 프로그램을 서비스 소켓이 없는 컨테이너에서 실행합니다.
- **CI 처리**: 발주자 결정에 따라 보고용입니다. CI 성패와 분리했고, 실행 요약에 표로 표시합니다.

### F-02 [낮음] 판정 불가가 CI에서 성공으로 끝남
- **위치**: `.github/workflows/ci.yml`의 시험 단계. 판정 불가 시험은 건너뜀(SKIP)으로 끝나고, 작업은 성공으로 끝납니다.
- **시나리오**: 실행기 환경이 바뀌어 격리를 만들지 못하면, 격리 시험이 모두 건너뜀이 되어도 CI는 초록색으로 끝납니다.
- **해결책**: 워크플로 시험 단계에 `MZK_REQUIRE_ISOLATION: "1"`을 추가합니다. 시험 코드 쪽은 이미 지원하며, 판정 불가를 실패로 바꾸는지는 isolation-failure 시험으로 확인했습니다. **워크플로 변경은 발주자 승인 대기 중이라 아직 적용하지 않았습니다.**

### F-03 [낮음] root로 시험하면 sudo 방법의 권한 확인이 실패함
- **위치**: `harness/isolate.mjs`의 sudo 방법
- **내용**: root가 sudo 방법을 쓰면 setpriv가 root로 "되돌아가" 권한이 남습니다. 시험은 이것을 **실패로 정확히 잡습니다**(Claude 로컬 실행에서 확인). 결함이 아니라 "시험은 일반 사용자로 돌린다"는 전제를 기록해 둡니다.

| R-07 | **자원 제한**(메모리·CPU·파일 크기·실행 시간) | 악성 로그로 인한 자원 고갈 방지 |
| R-08 | 격리 설정 자체를 **시험으로 검증**(이번 시험 장치 재사용: 대조 시험, 실패 시험, 판정 불가 구분) | 설정이 실수로 풀려도 CI가 잡도록 |
